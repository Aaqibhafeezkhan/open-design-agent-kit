## Why

Every bundled design system is two vendored files that are meant to describe one look: `DESIGN.md` (prose plus named values) and `tokens.css` (the values previews and artifacts actually use). In many systems they describe two different looks.

57 bundled systems have a `DESIGN.md` written from upstream's template, the one whose colour bullets end "Token from style foundations". An audit of those 57 (2026-10-22) found:

- **48** have a `DESIGN.md` `**Primary:**` colour that differs from the resolved `--accent`, even after the 8 existing local overrides (`packages/content/local/design-systems/*/tokens.override.css`).
- **46** name a different primary font from `--font-body`. 48 of the 57 `tokens.css` files use Inter, while their `DESIGN.md` files name Nunito, Playfair Display, Poppins and others.
- Placeholders show up on **both** sides. 15 of the 48 colour conflicts have a `DESIGN.md` primary of `#3b82f6` (Tailwind blue). The 8 existing overrides were made because `tokens.css` had the placeholder `#2563eb`.
- Some conflicts are two different brands, not a placeholder. `lingo`'s `DESIGN.md` is a playful green `#58CC02` with Nunito and "tactile 3D borders"; its `tokens.css` header says "global localization product language, soft violet action" with `#6d4aff` and Inter. `agentic` is orange `#FF5701` with Playfair in `DESIGN.md`, and blue `#60a5fa` with Inter in `tokens.css`.

This matters wherever both files reach the model. A brief built from `prepare_open_design_brief` includes the `DESIGN.md` body, while the preview and token instructions use `tokens.css`. A design system exported to Claude Design with `scripts/claude-design-system.ts` carries both, and the person who tried `lingo` there found the result unconvincing. The model is given two brands and blends them.

The existing fix only covers one direction. A `tokens.override.css` can make tokens agree with `DESIGN.md`. Nothing can make `DESIGN.md` agree with tokens, and no check notices a new conflict when upstream changes.

## What Changes

- **A consistency audit.** A new script, `packages/content/scripts/audit-design-system-consistency.mjs`, compares each bundled system's `DESIGN.md` values with its resolved tokens (vendored `tokens.css` plus any local override). The `DESIGN.md` values checked are the template's Primary, Secondary, Success, Warning, Danger, Surface and Text colours, the primary/display/mono families, and the type and spacing scales. Each system is classified as `consistent`, `tokens-placeholder`, `design-placeholder` or `conflict`, and the script prints a review table with both values side by side. Systems with a hand-written `DESIGN.md`, with no template bullets, are checked only for colours and fonts they name explicitly.
- **A recorded decision per system.** A new file, `packages/content/local/design-system-sources.json`, records for each inconsistent system which side is the truth (`"tokens"` or `"design"`) and a one-line reason. The audit suggests a default: the placeholder side loses, and in a genuine conflict it suggests `tokens` (what renders today). Every `conflict` row still needs a person's call. For example, `lingo`'s name and summary say playful green, so its truth is probably `design`.
- **A fix in both directions, both generated and never hand-written:**
  - **`design` is the truth** → the existing `tokens.override.css` shape, now generated by the script for colours, font stacks and type scale, not just the accent.
  - **`tokens` is the truth** → a new overlay file, `local/design-systems/<id>/DESIGN.sections.md`. It holds replacement `## Color`, `## Typography` and `## Spacing` sections, generated from the resolved tokens. Core's content index applies it when loading the design system: the vendored `DESIGN.md` stays untouched and the loaded body has those sections replaced. Prose sections (atmosphere, components, do and don't) are not touched.
- **Overlay shape rule widened.** An override folder may now hold `tokens.override.css`, `DESIGN.sections.md`, or both. A system can need both when, for example, its colour truth is `design` and its font truth is `tokens`.
- **A drift check.** `check-content-sync.mjs` fails when a bundled system is inconsistent after overlays and has no decision in `design-system-sources.json`. It also fails when a generated overlay is stale, meaning it differs from what the script would generate now. It reports an overlay as removable once upstream's own files agree, as it already does for token overrides.
- **Exports use the reconciled files.** `scripts/claude-design-system.ts export`, and anything else that reads a bundled design system, goes through the content index, so it gets the overlaid `DESIGN.md` and resolved tokens.
- **Upstream report.** The audit table goes to the upstream Open Design project as an issue, so the overlays can be deleted as upstream fixes them.

Not in this change: re-curating prose or summaries, the stale "152 design systems" count in `docs/guides/design-systems.md`, the ~10 summaries that say "dark" over light tokens (noted in the design-system-matching work), and custom `user:` systems (the URL-extraction change writes those consistently from the start).

## Capabilities

### New Capabilities
- `design-system-consistency`: the audit, the per-system decision file, the generated `DESIGN.sections.md` overlay and its application, and the drift check.

### Modified Capabilities
- `design-system-preview`: "Token Content Vendoring and Overrides" now allows the `DESIGN.sections.md` overlay beside `tokens.override.css`, and its drift rules cover both.

## Impact

- `packages/content/scripts/`: new `audit-design-system-consistency.mjs` (audit, suggest, generate), plus changes to `apply-local-overlay.mjs` (the widened shape rule) and `check-content-sync.mjs` (the new checks)
- `packages/content/local/`: new `design-system-sources.json`; new or updated overlays for about 50 systems; `README.md` documents the new shape
- `packages/core/src/content/contentIndex.ts`: apply `DESIGN.sections.md` when loading a bundled `DESIGN.md`
- `scripts/claude-design-system.ts`: read bundled systems through the content index
- Docs: `docs/contributing/content-sync.md` (the new overlay, the decision file, the audit command)
- No runtime dependencies and no change to custom design systems
