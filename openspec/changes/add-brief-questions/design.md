## Context

`surfaces.json` has `surfaces[]` (id, label, description, entries, `questions: string[]`) and `goals[]`. `list_open_design_skills` with `surface` returns a surface's entries, prompt and questions. The skill: "ask only the surface's questions the request doesn't answer". `prepare_open_design_brief` takes `skillId`, `designSystemId`, `brief`, collection fields, `sources`, `format`, `fluid` and returns instructions plus a suggested entry path. `recommend_open_design_design_systems` already returns `questions` that the skill asks "once, in one message, as short multiple-choice options … and accept 'you pick'".

## Goals / Non-Goals

**Goals:** at most one round of at most three questions, only when the answers change the design; every guess written down and shown to the user once; the same shape as the design-system recommender's questions so the agent learns one habit.

**Non-Goals:** an interview; questions generated by the server from the brief text (the agent judges what's answered); blocking the brief on unanswered questions; per-skill questions (surfaces are enough for now).

## Decisions

### Questions say what they change

A question earns its place only if different answers give a different design. `changes` makes that explicit and lets the agent drop a question whose answer is obvious from context. Example for `poster`:

```json
{ "id": "where", "text": "Where will it be seen?", "options": ["Printed", "On screens", "Both"], "default": "Both", "changes": "size, bleed and file type" }
```

### One merged round with the design-system questions

When the recommender also has questions, the agent asks both sets in the same message, still capped at three in total (surface questions first, since they decide what is built). This replaces two back-to-back question rounds.

### Assumptions on the brief, not just in chat

Putting `answers` and `assumptions` in the instructions makes the builder follow them; passing them to registration as `metadata.brief` makes them survive the conversation, so a later "make it lighter" can see "assumed dark theme" and the critic can judge fit against what was decided. Limits: six assumptions, 160 characters each, 2 KB total.

### Backward compatible content

The loader accepts a plain string as `{ id: slug(text), text }` with no options, so community or older content keeps working; the surfaces guard (`packages/content/scripts/surfaces.mjs`) warns on plain strings in `local/surfaces.json`.

## Risks / Trade-offs

- **Agents still over-ask.** Mitigation: "at most three", "none if the request is enough", and the eval briefs (`add-output-quality-evals`) include requests that should get zero questions.
- **Stale assumptions** after the user changes direction. The agent passes new `assumptions` on the next brief; the manifest keeps only the latest.
